# PoolDocAI — Owner Launch Directive: Domain, Email, SMS, and Every Nonbilling Feature
**Decision date:** 2026-10-24. **Status:** binding product acceptance specification, NOT proof of implementation or authority to deploy.
**Commercial exception:** The ONLY feature explicitly exempted from the launch-ready requirement is customer payment processing / checkout / subscription billing, including automatic paid seat and pooled-session add-on purchases. Existing owner-approved prices/quotas remain commercially fixed (see `docs/approved-pricing-and-entitlements-2026-10-24.md`). A manually provisioned pilot/early-access account may work without payment; do not silently activate Stripe. Public pages must show truthfully that billing is disabled and avoid misleading customer sign-up offers.

## 1. Durable owner launch rule
**When PoolDocAI launches publicly at its own `pooldocai.com` domain (or another explicitly selected owned domain), EVERY featured or advertised nonbilling user workflow must be implemented, secure, integrated and validated end to end.** A mock UI, feature chip, placeholder, untested Edge Function, READY UI-only preview, green syntax build, unchecked checkbox or database table does NOT count as a working feature. Includes **REAL SMS/texting**, not merely a phone input or an `sms_notifications_enabled` setting. Includes working tech + homeowner troubleshooting and complete document ingestion/retrieval. The owner has NOT authorized launch now, production code merge, production DB writes, commercial SMS spend or enabling payments. Keep launch as a gated event needing separate explicit owner approval after passing documented tests.

Only billable financial transactions are exempt; **seat permissions, access controls, monthly pooled case metering, plan behavior for manually provisioned pilot accounts, trial expiry and usage dashboards are NOT exempt** merely because paid billing is disabled.

## 5. Testing protocol and release gates
1. **One executor:** AntiGravity must first ACK Issue #15 and check latest PR HEAD before any shared-file edits; no parallel overwrite of in-flight TASK-005 fixes. Bounded commits and independent ChatGPT review.
2. **Real isolated staging:** obtain owner go-ahead before creating paid infrastructure; run migrations against a clean/staged DB, seed fake A/B tenant records with consent and no real customer PII, connect actual stage Edge/worker/widget/SMS sandbox/real test messaging and SMTP. Testing directly against live production company records is not authorized.
3. **Artifacts required per feature:** source commit SHA; specific browser/phone & server endpoint; passing unit/integration/negative/E2E tests; service delivery receipts where email/SMS; tenant identity/permission checks; screenshots/log correlation; known issues.
4. **No silent feature retirement:** Feature cannot pass when button merely exists or is disabled or returns 501, and avoid presenting false "available now". Log MISSING vs BLOCKED ON ACCOUNT vs CODE BUILT vs E2E PASS separately.
5. **Release control:** no merge/main, domain purchase, DNS cutover, production deploy/migrations, paid SMS, Stripe or enrollment/real customer communications merely because checklist/document/CI complete. Publish only after separate explicit owner go/no-go review. Billing is disabled and remains excluded.
