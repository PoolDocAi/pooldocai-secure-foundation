# Article intake and automated review

Owner workflow: Library → Import draft → choose DOCX, MD, TXT or `pooldocai-resource-v1` JSON → Validate and create draft. DOCX/MD/TXT require a category. Files are limited to 1 MB and extracted text to 200,000 characters. PDFs, macro-enabled Word files, embedded objects and Word fields are rejected. DOCX imports paragraph text only; check headings, tables, references and image permissions against the original. Uploaded bytes are not retained in Storage or exposed publicly. A source SHA-256 is supplied with the downloadable review report; it is not a trusted-source approval or a durable source archive.

The editor's **Run automated article review** saves pending edits, then screens that saved version. Findings include evidence excerpts and suggested fixes for editorial placeholders/metadata, technical procedure/value mentions, chemical/electrical/safety language, source references, SEO metadata and overlap with up to 199 other accessible drafts. Reports name the version, content checksum, engine and coverage limitations. Download the report before closing it if a permanent record is needed; reports are computed on demand and are not persisted by this release. Any edit requires a new report. Review checksum identifies the screening input; use the separate database release dialog's revision ID/checksum for publication authorization.

This is deterministic screening, not an LLM or external fact-checking service. Source contents are not fetched. Passing rules does not establish technical correctness or safety. A qualified human must check current original sources and equipment context. Suggested changes are not applied automatically. The review engine has no write, approval, publication, image-rights or diagnostic-knowledge capability. Existing editorial approval, exact-revision owner confirmation, holds, image rights, unpublish and rollback remain authoritative. The approved-source collection importer remains a separate checksum/allowlist path.

All new endpoints run behind existing verified identity, CMS membership, origin and CSRF checks; no service credential, schema change, Auth provisioning or new permission is required. Duplicate comparison uses only rows returned through the caller's existing database adapter. Reports and endpoints use no-store caching. JSON parsing errors do not echo manuscripts.

Validation on October 28, 2026: 9 focused intake/review tests; actual production HTTP app and PostgreSQL adapter upload/review/draft-no-leak checks; owner publication, private media, auth and dynamic public-delivery regressions; real Edge browser at 390 and 1440 pixels covering upload, findings, report download, edit/save/review and accessibility. Local browser uses synthetic identity/database; PostgreSQL tests use PGlite with documented transport emulation. No hosted acceptance is inferred. Private fixture was neither required nor fabricated. Production, held drafts, schedules, PDFs, 2FA and marketing source were not modified.
